先核对当前主机、CCBox 版本和报错原文。操作结果不确定时先读取最新状态，再决定重试。不要用清空个人目录、删除虚拟磁盘或重建账户作为常规排障手段。

报错会先说明失败的操作，再说明当前能确认的原因。例如，“上传窗口已关闭”需要重新打开应用内的文件窗口；“等待响应超时”应先检查连接；“磁盘剩余空间不足”应先释放环境所在磁盘的空间。看到“尚未取得可识别的原因”时，保留提示中的 HTTP 状态或退出码，打开“操作详情”，并在设置的“环境与恢复”中导出诊断包。

“联网检查未通过”会列出具体项目及检测结果。“未能确认”表示没有取得足够结果；它不会被当作检查通过，外网继续关闭。点击提示旁的“查看检查清单”可以查看其他项目和处理建议，无需猜测是哪一项阻止联网。

## 下载或安装失败

| 现象 | 处理方式 |
| --- | --- |
| 没有适用的安装包 | 向 CCBox 安装包提供方确认平台和处理器架构，或使用本地源码构建。 |
| Mac 显示损坏、无法验证或不支持 | 核对 Apple Silicon、macOS 14+，重新下载完整 DMG，检查该版签名、公证和校验说明。保留系统原文，不关闭系统验证来掩盖问题。 |
| Windows 未知发布者 | 确认是否为明确标注的未签名预览，阅读对应发行说明；不能把它当作已签名发行。 |
| Windows 安装 Debian 或 Ubuntu 时提示“准备镜像失败” | 打开“操作详情”，按下方的 [Windows 虚拟化与镜像安装](#windows-虚拟化与镜像安装) 排查。 |
| Linux 无法启动 | 确认 x86_64、支持发行版与 KVM 权限，使用 APT 补齐安装依赖。选择 Debian 或 Ubuntu 时，页面会提示 `/dev/kvm` 缺失或无权访问等具体原因和处理命令。 |
| 缺少代理核心 | 重装对应平台完整应用，不要只复制单个命令行文件。 |

## Windows 虚拟化与镜像安装

在 Windows 上选择 Debian 或 Ubuntu 后，CCBox 会先检查这台电脑能否运行 Linux 虚拟机，再开始下载镜像。检查没有通过时，“客户机系统”下方会显示具体原因、处理步骤和可用的按钮；处理完成前，安装按钮保持不可用，不会白白下载镜像。已经创建好的环境照常启动，不受这项检查影响。

| 提示的原因 | 处理方式 |
| --- | --- |
| Windows 虚拟机监控程序平台尚未启用 | 点击“一键启用”，在 Windows 管理员授权窗口中选择“是”。启用完成后点击“立即重启”，重启后回到 CCBox 继续安装。 |
| CPU 虚拟化在 BIOS/UEFI 中处于关闭状态 | 按页面列出的按键和选项进入固件设置开启虚拟化，或点击“重启并进入 BIOS 设置”。回到 Windows 后，再按提示点击“一键启用”。 |
| 设置已完成，需要重启电脑 | 保存其他程序中的工作，点击“立即重启”或手动重启。 |
| Windows 虚拟机监控程序没有运行 | 点击“一键启用”，它会同时恢复 Windows 的虚拟机监控程序启动设置。若曾为安卓模拟器关闭 Hyper-V，或安全软件开启了“核晶防护”等独占虚拟化的功能，请先关闭这些设置再重启。 |
| 当前 Windows 运行在虚拟机或云主机中 | 需要在外层宿主机或云平台为这台虚拟机开启嵌套虚拟化，CCBox 无法在虚拟机内部开启。 |
| 无法查询 Windows 虚拟化状态（HRESULT …） | 说明 CCBox 未能读取虚拟化状态，并不代表固件设置有误。先点击“一键启用”并重启；仍失败时导出诊断包并附上该 HRESULT。 |

“一键启用”只做两件事：启用“Windows 虚拟机监控程序平台”（Windows Hypervisor Platform），并把 Windows 的虚拟机监控程序启动设置恢复为自动。它需要 Windows 管理员授权，不会自动重启电脑；两种重启按钮都会先请你确认，并在 15 秒后重启。取消授权时设置不会改变。

### 在 BIOS/UEFI 中开启 CPU 虚拟化

页面会按电脑品牌和处理器给出进入固件设置的按键和选项名称。常见情况如下，具体以你的电脑为准：

| 品牌 | 开机时连续按 |
| --- | --- |
| 联想 | F2（部分机型为 Fn+F2）；ThinkPad 和台式机按 F1；也可在关机状态按机身的 Novo 小孔 |
| 戴尔 | F2 |
| 惠普 | Esc 后按 F10 |
| 华硕 | F2 或 Del |
| 宏碁 | F2 或 Del |
| 微星、技嘉、华擎等台式机主板 | Del |
| 华为、荣耀 | F2 |

- Intel 处理器：开启 Intel Virtualization Technology（也可能写作 VT-x、Intel VT、VMX）。
- AMD 处理器：开启 SVM Mode（也可能写作 AMD-V、SVM、Virtualization）。
- 选项常在 Advanced、Advanced → CPU Configuration、Configuration、Security 或 Virtualization Support 中。改为 Enabled 后保存并退出，通常按 F10。

不确定按键时，可以从 Windows 进入固件设置。Windows 11：设置 → 系统 → 恢复 → 高级启动“立即重新启动” → 疑难解答 → 高级选项 → UEFI 固件设置。Windows 10：设置 → 更新和安全 → 恢复 → 高级启动“立即重新启动”，之后的路径相同。

### 手动检查

如需手动确认，可以打开“任务管理器 → 性能 → CPU”查看“虚拟化”状态；启用了 Hyper-V 等功能后，这里显示的状态可能不准确，以 CCBox 的检查结果为准。也可以在开始菜单搜索“启用或关闭 Windows 功能”，勾选“Windows 虚拟机监控程序平台”后重启，或在管理员终端运行：

```powershell
DISM /Online /Enable-Feature /FeatureName:HypervisorPlatform /All
```

处理完成后打开 CCBox，点击“重新检测”或“继续安装”。保留原来的环境存储目录，CCBox 会复用已校验的镜像。仍失败时，记录操作详情里的具体错误，按[导出诊断与反馈](#导出诊断与反馈)提供日志。

### 提示未找到可用的物理 IPv4 网卡

这条提示来自宿主机网络检查。请连接本机的以太网或 Wi-Fi，确认该网卡已连接、取得 IPv4 地址并配置了 IPv4 默认网关，然后在 CCBox 重新应用代理节点并重试。只有 VPN 或 TUN 虚拟网卡的 Windows 虚拟机或云主机无法通过这项检查，即使外层宿主机已提供嵌套虚拟化。

## 准备环境卡住或反复下载

打开“操作详情”区分仍在下载、安装依赖和已经失败。检查节点、剩余磁盘和存储盘连接后，点“继续安装”。仍有数据持续接收时可以等待，完整性校验未通过的文件不能使用。

| 错误 | 下一步 |
| --- | --- |
| `failed to download`，并显示镜像地址或 HTTP 状态 | 核对 Windows 主机的网络、系统代理或 TUN 到镜像站及其跳转目标的连通性。记录具体域名和状态码，再点“继续安装”。详见[系统镜像的下载网络](network.md#系统镜像的下载网络)。 |
| `Download interrupted` / `partial data retained` | 未完成文件已保留，修复网络后重试续传。 |
| `checksum mismatch` | 文件摘要不符，重新下载，不跳过校验。 |
| `Guest DNS could not resolve` | 检查节点及 DNS 配置，应用后重试。 |
| NodeSource / APT 失败 | 提示会列出失败的 APT 命令、涉及的软件包和已脱敏的错误输出末尾；域名解析失败先查 DNS，连接超时先查代理，找不到软件包说明软件源不可用。没有可识别原因时，保留这些信息并导出诊断包。 |
| APT 重复 `Tried to start delayed item` | 更新到包含 APT 修正的构建，旧版依赖管理器升级失败时先修复网络，不能继续依赖安装。 |
| Debian 客机更新环境组件时报 `chromium-l10n` 依赖冲突 | 检查操作详情中的 Chromium 版本和 Debian 安全仓库索引。若索引为空，使用包含索引修复的构建重试“更新环境组件”，让 APT 重新下载索引并安装兼容的语言包。 |

安装和启动不要求启用主机 Git 裸仓库保护。已有的主机 Git 设置会保留。如需调整，请先检查当前生效的 `safe.bareRepository` 配置。

## 节点已应用但无法联网

关键检查失败的提示旁有“查看检查清单”按钮，点击后可查看未通过项，展开可见检测证据与处理建议。底部网络状态也能打开同一份清单。“已应用”只表示节点选择成功，外网还需检查通过。

| 状态 | 处理方式 |
| --- | --- |
| 出口不符合静态 IP、城市或国家规则 | 切换最终出口会恢复该节点的绑定，首次使用时检测并绑定。同一节点出口变化时，确认后明确修改规则，重检保留原绑定。详见[出口规则](network.md#时区语言与出口规则)。 |
| 命中大陆网段或定位为中国大陆 | 换用非大陆出口，静态 IP 和不限地区均不能豁免。怀疑归属错误时保留检查报告。 |
| 代理核心未就绪 | 进入代理诊断检查状态，重新应用节点或重启 CCBox 核心。 |
| 端口占用 | 选一个未占用的 CCBox 独立端口，按提示重启，无需终止其他代理。 |
| 位置查询失败 | 重试或换节点；所有模式均须确认非大陆出口，手动时区和语言不能跳过国家或地区检查。 |
| 出口采样不完整 | 展开证据，查看缺失的是宿主、虚拟机终端还是浏览器，以及超时或 HTTP 状态；终端代理通过仍需其他路径成功。动态 IP 规则无法代替缺失的采样。 |
| 手动暂停或报告过期 | 确认后主动重新检查，全部关键项通过才恢复。 |
| “检查或监测授权已到期”反复出现 | 查看下文的续期排查，记录发生和恢复时间，导出诊断包。 |
| 主机切网后离线 | 等待恢复和完整复检；原手动暂停不会自行解除。 |

本机浏览器可联网不能证明 CCBox 代理已经配置。订阅无节点时检查是不是含 `proxies` / `payload` 的 YAML；不要把私人订阅上传到在线转换网站或 Issue。

### 联网许可反复到期

“检查或监测授权已到期”表示 CCBox 没能在短期许可到期前完成续期，环境会关闭外网。节点仍能访问网站时，也可能因检查调度等待或执行过慢发生到期；日志中同时出现代理错误时，仍需核对节点。

先查看检查清单和“操作详情”，记录离线、完整重检开始与恢复的时间。非人为暂停的环境会尝试完整复检，网络状态会显示等待时间或原因；手动暂停需主动恢复。安全监测独立于生命周期操作锁运行，完整复检仍需等待当前操作结束。若反复发生，在复现后从设置导出诊断包；维护者可据此区分操作锁等待、网卡查询、代理检查、环境核验、续期请求与恢复等待。等待恢复时，已保存文件和离线终端仍可使用。

当前源码的诊断日志用固定服务标识 `icanhazip` 和 `ipify` 记录每次出口查询的耗时与错误，导出时保留这些标识。诊断包中的 `logs/`、`safety/latest-report.json` 和 `manifest.json` 可用于定位失败阶段；分享前仍须检查脱敏结果。旧版安装包可能缺少分阶段诊断或超时重试，需同时提供应用版本，不能只根据源码判断已安装版的行为。

## 任务退出 137 或重任务后断网

137 表示被强制终止，无法独立证明 OOM。到“设置 → 环境与恢复 → 计算资源”查看环境启动后的 OOM 计数、上限和用量，再导出日志。OOM 计数增加表示客机曾因内存不足终止进程，具体进程需结合日志。

旧环境上限较低时，保存工作后重启应用已保存资源配置；到达上限则降低编译、渲染或其他并行任务数。重任务还可能使检查超时并触发外网关闭，恢复须通过完整复检。

## 原账户与数据看不见了

再次出现创建账户通常意味着当前配置目录找不到原账户。核对默认 `.ccbox`、显式 `CCBOX_CONFIG`、原环境存储及当前本机/SSH 主机。先保留现场，不新建账户，不只拷贝 `account.json`。

原目录需连同收藏、密码库、配置与持久磁盘保留。迁移前停止相关后台、做完整备份，再恢复同一套数据。快捷登录绑定原目录时，迁移后用原密码解锁并重新授权。系统钥匙串暂不可用时，使用密码并点“重新检查快捷登录”。

## Claude 登录与账号异常

主机已有登录不会自动导入。到 CCBox 内的 Claude 终端完成官方授权，账号面板核对身份后“加入调度”。网页、Desktop 和 CLI 登录分别管理。

“暂无可分配账号”时检查登录是否有效、是否参与自动分配、额度与重置时间，点击“检查状态”。普通终端换身份后新账号要重新加入。额度读数缺失或过旧时不能把旧百分比当实时承诺。

同一账号通过“登录新账号”授权后仍要求登录时，先等待该账号的手机任务结束，关闭使用它的终端，再从原账号卡片点击“打开登录终端”或“重新登录”。自动恢复仅适用于 macOS、Linux 中缺少文件凭据的独立账号；已有凭据、钥匙串登录、Windows 环境或检查失败时需要从原入口完成授权。原目录、会话和设置会保留，无需删除账号或重建环境。

模型仍拒绝请求时记录官方错误类型，核对使用资格与关键网络检查。能打开授权页只说明网页可达，完成授权和一次真实请求后才能确认使用成功。

历史列表提示“未能读取”时，已读取会话保留，活跃标记暂时清除。点击重试按钮，等待读取完成。Windows 提示会区分配置、配对校验、连接、通信和请求超时；只有明确的桌面状态错误才要求登录或解锁客机。不要仅凭读取失败就重新登录 Claude。持续失败时复制完整原因并导出诊断包。

账号交接被阻止时，先处理未完成工具、审批、待发消息和后台任务，再核对接续分组、目标登录与额度。交接失败沿用原操作重试，准备阶段也可取消；不要重新发送旧消息来恢复历史。详细授权条件见[同一会话换账号](accounts.md#在同一会话中换账号)。

## 浏览器、Desktop 或文件上传异常

浏览器白屏或待恢复时点“恢复浏览器”。整个界面中断时重开 App；异常页可“重新加载界面”或导出诊断。`localhost` 应在 CCBox 内启动服务。

Desktop 画面比例异常时先设“显示大小”为 100%，点“重试调整”。更新组件后保存工作、关闭再打开 Desktop。上传仍显示内部目录或出现 “The file picker didn’t open” 时，同样先同步组件再重开应用。

Desktop 文件服务退出或连接中断时，CCBox 会提示原因并降低重试频率；恢复后自动继续读取文件请求。反复提示服务退出时，重新打开 Desktop，并在资源设置与诊断日志中检查应用退出原因。

Windows 客机的官方 Desktop 在 Code 模式选择共享项目后提示“Claude 无法打开该文件夹”，或界面像是卡住时，对话框可能只出现在客机桌面。共享项目请在 CCBox 终端中使用，需要 Desktop 时改选客机本地磁盘上的文件夹，详见 [选择项目与传文件](desktop.md#windows-客机官方-desktop-提示claude-无法打开该文件夹)。

共享项目出现 Git 文件所有者错误时，更新 CCBox 后重新连接项目；新连接会使用环境内的用户编号显示文件。Git 远程操作出现主机密钥或认证错误时，需要在客机中完成相应的 Git 认证和主机身份核验。

清空普通会话全部 Cookie 后，编辑器认证会失效，点“恢复编辑器”。密码、扩展或 Cookie 功能入口不可用时，核对应用和环境组件版本。网站拒绝附件还需检查自身格式与大小限制。

## 手机连接

当前桌面客户端已停用手机配对和中继。通过电脑连接服务器，请参阅[云端部署与 SSH](cloud.md)。

## Tailscale 登录或 SSH 失败

先确认 CCBox 环境已启动并通过网络检查，组件已安装，本机 Tailscale 与 CCBox 加入同一私网。登录页面由 CCBox 浏览器打开，启用设备审批的网络还需管理员批准。

本机连 CCBox 时，核对公钥已加入面板、使用面板显示的实际客机用户名与地址，并检查私网访问规则。CCBox 连本机时，本机还需开启 SSH 服务并允许认证；Tailscale 登录不自动提供本机 SSH 权限。不要把私钥粘贴到公钥输入框。

暂停外网、代理中断或停止环境会影响私网连接。“断开”保留身份与公钥，“退出登录”要求下次重新授权。真实账号授权与安装环境的完整连接仍待验收，当前范围见[Tailscale 指南](tailscale.md)。

## SSH 或云端部署失败

先确认 SSH 地址、端口、用户、认证方式和服务器网络。主机指纹变化时独立核对，避免直接接受未知身份。首次部署失败需检查 Linux x86_64、cgroup v2、systemd 用户服务、UID/GID 映射及 FUSE/TUN 前提。

服务退出时重连可尝试启动；持续失败查看用户服务日志。关闭本机 App 不停止远端，若希望停止任务，须在对应服务器工作台停止环境。无人登录后服务停止时由管理员检查 linger；服务器重启恢复需单独配置和验证。

不要通过删除容器、引擎 data-root 或账户修复部署。连接中断时先核对操作是否已完成，再重试有写入效果的动作。

## 导出诊断与反馈

在“设置 → 环境与恢复”的日志诊断中导出 ZIP。云端导出需保持连接；界面打不开时可用安装包内的 CCBox 命令：

```sh
cage diagnostics --json /absolute/path/cage-diagnostics.zip
```

macOS 命令在 `ccBox.app/Contents/Resources/cage`，Windows 在安装目录 `resources\cage.exe`，Linux 位于应用目录。使用本机绝对输出路径；控制服务不可用时仍可导出本机日志。

向 安装包提供方提供应用版本、操作系统、处理器架构、当前模式、复现步骤、期望结果与错误原文。分享前检查诊断和截图，遮盖账号、IP、路径、代理凭据和授权链接。不要上传整个配置目录、完整订阅或项目内容。
